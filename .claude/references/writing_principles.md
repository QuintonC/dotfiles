# Writing Principles

Apply these when producing any prose: PR descriptions, docs, memos, Slack/email drafts, release notes, or commit bodies longer than one line. Not for code comments — those follow the global CLAUDE.md rule (rare, WHY-not-WHAT).

## Style

- **ecommerce** (never e-commerce, Ecommerce, eCommerce).
- **internet** lowercase.
- **Oxford comma.**
- **Sentence case** for titles ("Like this one here", not "Like This One Here").
- **One** space between sentences.
- **American English** ("realize", not "realise").

## Write simple

- **No idioms.** They don't translate and they exclude non-native readers.
- **Curb acronyms.** If an acronym is unavoidable, spell it out on first reference.
- **No lingo.** If only the in-group can parse it, don't use it.
- **Link generously.** If a draft refers to another topic, link to it rather than explaining inline.
- **Avoid name-dropping your own team, company, or product in memos.** Ideal count: 0. Max: 1 if it truly adds context.

## Voice

- **Active > passive.** Subject first, then action. "They decided to present the idea" beats "It was decided that the idea should be presented."
  - Exception: when the concrete thing is the subject of the sentence, passive can lead. "Migration plans are written by each team…" is fine because the migration plan is what's being defined.
- **Positive > negative.** "The writer did a poor job" beats "The writer didn't do a good job." Frames what the subject did, not what it didn't.

## Rhythm

- **Vary sentence length.** Short sentences drive clarity. Long ones build context or suspense. Monotone is boring.
- **Blank lines between paragraphs** (not indentation).
- **Bold/italic sparingly.** Distracting when overused.

## Polish

- **Edit proportional to audience + formality.** Small internal → minimal edits. Large external → maximum edits. Always aim for minimal length.
- **Never too formal** unless the document is legal or regulatory.

## Two killer revision tricks

1. **Take the second-to-last paragraph, make it the first, then cut everything no longer needed.** Almost always works.
2. **Would I explain this to a friend in a bar the same way?** If no, replace the draft with the bar explanation.

## Self-check before sending

1. Does every sentence earn its place? Cut anything that restates what the diff, link, or surrounding context already shows.
2. Is my own team/company/product named more than once? Cut.
3. Any passive voice that isn't about a concrete subject? Flip it.
4. Any negative framing I could flip? Flip it.
5. Any acronym without a spelled-out first reference? Fix.
6. Any idiom or lingo? Replace with plain words.
7. Do sentence lengths vary, or is it monotone?
8. Would the bar-explanation be shorter and clearer? If yes, use that.
